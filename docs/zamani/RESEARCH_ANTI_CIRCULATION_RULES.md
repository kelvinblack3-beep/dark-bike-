# Project Zamani — Research Anti-Circulation Rules

Purpose
This file codifies procedures to prevent circular re-investigation of already-archived/rejected architectures and to ensure each new research investigation clearly states what is new.

Before proposing a new Project Zamani power architecture, every AI or research engineer must:

1. Read docs/zamani/PROJECT_ZAMANI_MASTER_STATE.md
2. Read docs/zamani/PROJECT_ZAMANI_MEMORY.md
3. Read the relevant research matrix (e.g., ZAM-P1_PLASMA_ARCHITECTURE_MATRIX.md)
4. Read relevant failure-log entries (e.g., failure-log/ZAM-P1_PLASMA_FAILURES.md)
5. Check whether the proposed architecture has already been investigated
6. If already investigated, explicitly document what new boundary condition, technology, evidence, or calculation makes the new investigation different
7. Never restart a rejected architecture merely because it has been renamed
8. Never overwrite a previous failed result; preserve contradictions and explain them
9. Use and preserve status labels: VERIFIED | SUPPORTED | PROVISIONAL | UNVERIFIED | REJECTED | FUNDAMENTALLY FAILED | BREAKTHROUGH CANDIDATE
10. Every new research session must reference previous relevant session IDs and failure IDs

CORE RULE
"DO NOT REDISCOVER THE SAME IDEA. EXTEND IT, REFUTE IT WITH NEW EVIDENCE, OR CLOSE IT."
